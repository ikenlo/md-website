# md-website

Сайт салону краси **M&D beauty salon** з онлайн-записом, синхронізованим з **MDs connect**.

## Структура

```
index.html          — сторінка (Hero, послуги, про нас, прайс, онлайн-запис, галерея, контакти)
css/styles.css      — стилі (темно-зелений + золото), адаптив під мобільні
js/config.js        — налаштування: mode "mock" | "api"
js/api.js           — шар інтеграції з MDs connect (+ демо-дані)
js/booking.js       — віджет запису: послуга → майстер → дата/час → контакти
server/proxy.js     — сервер: статика + захищений проксі до MDs connect (токен тут)
docs/API.md         — контракт API, який сайт очікує від MDs connect
assets/img/         — фото (зараз — тимчасові, вирізані з макету)
```

## Запуск

Демо (без MDs connect, дані тестові):
```bash
node server/proxy.js      # http://localhost:8080
```

З реальним MDs connect:
1. `cp .env.example .env` і вписати `MDS_CONNECT_URL` та `MDS_CONNECT_TOKEN`.
2. У `js/config.js` змінити `mode: "mock"` → `mode: "api"`.
3. `node server/proxy.js`

## Чому через проксі, а не токен у сайті

Усе, що лежить у JS сайту, може прочитати будь-який відвідувач. Якщо покласти туди
токен MDs connect — його можна вкрасти і, наприклад, видаляти чи створювати записи.
Тому токен живе лише на сервері, а браузер звертається до `/api/...`.
